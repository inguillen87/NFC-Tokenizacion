Authoritative scope: [`docs/NEXID_GOAL_SYNGENTA_PACKAGING_ENTERPRISE.md`](../../NEXID_GOAL_SYNGENTA_PACKAGING_ENTERPRISE.md).

This is the working acceptance ledger for the current checkout. `IMPLEMENTED` means there is direct code and passing test evidence. Two independent clean disposable-Neon installations prove the complete 97/97 migration chain through 0095. The current checkout adds migration 0096 as the 98th migration; its static contracts, release gates and migration-safety checks pass, but 0096 has not yet been executed on PostgreSQL/Neon and is not covered by the earlier 97/97 receipts. Separate sanitized receipts prove the ephemeral least-privilege runtime-role ACL on the 97-migration schema, direct-function SUN/TT persistence behavior and direct-function supplier atomicity, isolation and serialization behavior. The earlier 95/95 through 0093 and incremental 0094 receipts remain archived below as historical checkpoints. None of this means deployed or migrated in production, exercised through the HTTP routes, physically validated, HSM-backed, or proven against an external webhook receiver or live blockchain/RPC. Those claims require their own evidence.

## External evidence boundaries

- The earlier 95-migration chain through 0093 remains valid historical evidence. The current disposable evidence supersedes it for checkout readiness with two clean 97/97 runs through 0095; neither is a production migration or a full runtime ceremony.
- Migration 0094 is the current SUN database-authorization boundary: the public wrapper is the only grantable persistence entry point, its fixed `SECURITY DEFINER` path cannot be populated by the runtime role, and internal bases remain private. `SECURITY DEFINER` is not KMS, not HSM and not hardware-backed secret custody.
- Migration 0095 is a database-level conflict-target correction for durable TT receipts. It requires the exact named primary key and preserves the wrapper/base ACL and physical NFC semantics. Clean 97/97 Neon installation and direct-function persistence are proven, but physical NFC behavior and the HTTP route are not.
- Migration 0096 changes enterprise role-profile defaults and versions deterministic software risk scoring. Its contracts, 193/193 auth suite, 14/14 migration gates and migration-safety checks pass locally, but its SQL and bounded backfill have not run on PostgreSQL/Neon. It changes no physical NFC cryptography and makes no managed-KMS/HSM claim.
- Migration 0090 does not silently delete historical key rows on non-SUN carriers. Its constraint is `NOT VALID`; export fails closed until an explicit audited reconciliation and later constraint validation.
- Migration 0092 closes null/mismatched supplier-order scope bypasses and rejects carrier-mismatched manifest rows. Migration 0093 binds persisted TT truth to canonical raw evidence and permits `force_result` only to degrade trust.
- The physical NFC path is not certified by source or direct-function database tests. Real configured NTAG 424 DNA/TT taps, sacrificial opening evidence and packaging-line validation are still required.
- Application-envelope custody is not Google Cloud KMS and is not HSM-backed.
- Local webhook tests do not prove an external receiver, local chain tests do not prove a current RPC transaction, direct-function QA does not prove the HTTP routes, and local builds do not prove deployment.
- No production migration, database-role/grant change, deployment, DNS change, provider write or blockchain transaction was executed in this worktree validation.
- The new loopback HTTP harness crosses real local TCP/HTTP into production route handlers, but it does not exercise Next.js routing middleware, TLS termination or external infrastructure. Its complete PostgreSQL-backed ceremony remains pending until an explicitly disposable local `nexid_e2e` database exists.
